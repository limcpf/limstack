# 문서 작성과 공개

limstack 프로젝트는 `~/dev/limstack`에 두고, 로컬 문서 입력 루트는 `~/documents`로 지정해. Syncthing 동기화 대상은 `~/documents/markdowns`와 `~/documents/images` 두 폴더뿐이야. `~/documents` 자체는 동기화 대상에서 제외돼. 명령을 실행할 때 문서 루트를 지정할 수 있게 해서, 다른 머신에서도 같은 폴더 구조를 읽을 수 있게 해줘.

```text
~/documents/
├── markdowns/
│   ├── java/servlet-request-flow.md
│   ├── spring/transaction.md
│   └── limstack/example.md
└── images/
    └── java/servlet-flow.svg
```

- stack 폴더 바로 아래에 `.md` 파일을 둬. `java/servlet-request-flow.md`의 주소는 `/stack/java/servlet-request-flow/`야. stack과 URL은 파일 경로에서 결정하고, 제목을 바꿔도 주소는 유지해줘. 다른 stack에서 같은 파일명을 쓸 수 있어야 해.
- `title`과 `date`는 필수, `description`과 `publish`는 선택이야. 날짜는 `YYYY-MM-DD`로 써. `publish: true`를 명시한 글만 공개 목록과 페이지에 포함해줘. `publish`를 생략한 글은 초안으로 취급해.
- `![요청 흐름](../../images/java/servlet-flow.svg)` 같은 상대 경로 이미지를 지원해줘. `dist/`에는 공개 글이 참조하는 문서 이미지만 포함해. 문서 사이 링크는 `/stack/java/servlet-request-flow/` 같은 사이트 경로를 기본으로 해줘.
- YAML 문법이 깨져 `publish` 값을 읽을 수 없으면 해당 파일을 건너뛰고 전체 빌드를 계속해줘. 터미널 경고에는 파일 경로, 확인 가능한 줄 번호, 건너뛴 이유를 표시해. 빌드가 끝나면 공개 글 수와 건너뛴 파일 수를 요약해줘.

## 초안과 문서 한 편 검토

- `npm run dev`에서 초안을 볼 수 있게 해줘. `npm run build:doc -- ~/documents/markdowns/limstack/example.md`는 `publish: false`이거나 `publish`를 생략한 글도 선택할 수 있어야 해. 선택한 글 한 편을 공개 사이트와 같은 렌더링 과정과 레이아웃으로 빌드하고, 결과를 `dist/`와 별도 위치에 저장해줘.
- `Example`은 `publish: false`로 두고 지원하는 Markdown 표현을 한 편에 담아줘. 모바일과 인쇄를 확인할 수 있도록 긴 코드와 넓은 표도 넣어줘. 공개 동작을 확인할 수 있는 예제 문서는 소수 추가해줘.
