# 세션 인수인계

## 현재 상태

limstack은 한글 기술 문서를 주제별로 모아 읽는 개인 정적 사이트야. **1차 로컬 구현안은 승인됐고, 현재는 설계 문서와 HTML 스케치까지 작성한 상태야.** Astro 프로젝트 생성, 빌드, 미리보기 검증은 앞으로 할 일이야. [화면 스케치](화면-스케치.html)는 홈과 문서 상세의 배치와 글꼴을 검토하는 예시야.

## 이어갈 때 알아둘 결정

- **문서 원본과 빌더** — 이 공개 저장소에는 빌더와 프로젝트 설계를 둬. 개인 콘텐츠는 외부 입력 루트인 `~/documents`의 `markdowns/`와 `images/`에서 읽는 구조야. 기존 Syncthing은 이 두 하위 폴더를 각각 동기화해. 설계 문서는 저장소의 `docs/`에서 관리하고, `markdowns/projects/limstack/`에는 프로젝트 소개와 GitHub 링크를 담은 `README.md` 하나만 둬.
- **공개와 검토** — stack 폴더 바로 아래의 Markdown 한 편이 문서 URL 하나에 대응해. 전체 공개 빌드에는 `publish: true`인 글만 포함해. 로컬 미리보기와 한 편 빌드에서는 초안과 검토용 `Example`도 읽을 수 있어. 공개 여부를 판별할 수 없는 YAML은 파일 위치와 이유를 경고하고 해당 글을 건너뛰어. [문서 작성과 공개](문서-작성과-공개.md)
- **읽기 화면** — 밝은 종이색의 단일 열에서 한글과 영문 본문은 Sarasa Gothic K, 코드와 경로는 Sarasa Mono K로 보여줘. 목차는 기본으로 접어둬. 스케치에는 예문에 쓰인 글자만 내장했어. 실제 사이트에서는 새 글에 등장하는 한글도 표시할 수 있어야 해. [읽기 화면](읽기-화면.md)
- **2차 배포** — 비공개 문서 저장소에서 문서 커밋과 빌더 버전을 지정해 수동 빌드하고, 변경된 글과 메뉴·목록 전체 캡처를 Telegram으로 검토하는 설계야. GitHub에서 선택한 빌드의 `dist/`를 Cloudflare에 배포하고, 실패하면 같은 결과물로 재시도해. 외부 서비스 연동은 1차 로컬 사이트를 완성한 뒤 진행할 작업이야. [검토와 배포](검토와-배포.md)

## 이번 세션에서 정한 개발 방식

협업 기준을 저장소 README와 `AGENTS.md`에 정리하고 `docs/pr-workflow` 브랜치에서 [PR #1](https://github.com/limcpf/limstack/pull/1)을 열었어. 명령과 계산 예시는 [저장소 README](../README.md)에 있어.

- **PR 크기** — 독립적으로 검증할 동작 하나를 담아. 사람과 AI가 작성한 변경은 추가·삭제 합계 100줄 안팎을 목표로 하고 200줄을 상한으로 둬. 생성 파일은 따로 세고, 업무 판단이나 복잡한 처리의 이유를 설명하는 주석 전용 줄은 뺄 수 있어. 코드가 함께 있는 줄은 세고, 코드를 주석에 숨겨 상한을 피하는 건 금지해.
- **작업 분리** — 새 PR마다 전용 브랜치와 Git worktree를 써. 같은 PR의 후속 수정은 기존 worktree에서 이어가. 공통 변경을 먼저 병합한 뒤 독립적인 작업은 각 worktree에서 병렬로 진행해.
- **리뷰와 학습** — 커밋과 PR의 제목·본문은 한국어로 써. 개발·리뷰에는 `ponytail:ponytail`을 적용해 코드가 필요한지, 기존 기능으로 해결할 수 있는지 따져. AI는 PR마다 직접 해볼 실습이나 리뷰 질문 하나를 제안해.
- **학습 기록** — 검증한 개선 사례는 `~/documents/markdowns/knowledge/`에 판단 근거와 결과를 남겨. 첫 기록은 `PR에서 설명 주석을 변경 줄 수와 구분하기.md`야.

## 다음 작업

다음 세션에서는 PR #1의 병합 여부를 먼저 확인해. 리뷰 반영이 남았으면 `git worktree list`에서 `docs/pr-workflow` 작업 폴더를 찾아 이어가.

1차 구현 요청을 받으면 [로컬 구현](로컬-구현.md)의 완료 조건에서 시작해. `npm run dev`, `npm run build:doc`, `npm run build`, `npm run preview`는 구현할 명령이야. 현재 체크아웃에서 실제로 실행되는지는 그때 확인해.

Mermaid 조판 기준과 Spring MVC 분기 예시는 [읽기 화면](읽기-화면.md#mermaid-다이어그램)에 정리했어. 1차 구현 때 비공개 `Example`에서 한글 레이블, 넓은 시퀀스 그림의 모바일 스크롤, 흑백 인쇄를 확인해.
