# limstack

한글 기술 문서를 주제별로 읽는 개인 정적 사이트. [설계 목차](docs/README.md) · [현재 상태](docs/세션-인수인계.md)

## PR 크기

- **단위** — 독립적으로 검증할 변경 하나와 확인 방법. [작은 PR의 기준](https://google.github.io/eng-practices/review/developer/small-cls.html)
- **범위** — 추가 + 삭제 **100줄 안팎, 최대 200줄**. 초과 예상 시 구현 전 분할.
- **집계** — 사람·AI가 작성한 코드, 테스트, 설정, 문서 포함. 확인 명령 `git diff --numstat origin/main...HEAD`.
- **주석** — 업무 판단·복잡한 처리의 이유만 적은 줄은 제외 가능. 코드가 섞인 줄은 포함. 줄 수를 줄이려는 코드 주석 처리 금지.
- **생성 파일** — 별도 집계. PR에 파일명·생성 이유·제외분 명시. 예시 `전체 130 − 잠금 파일 20 − 설명 주석 10 = 100줄`.

## 작업을 나누고 병렬로 진행하기

- **새 PR** — 완료 조건·선행 작업 명시. 전용 브랜치·Git worktree 사용. 후속 수정은 같은 worktree에서 진행.
- **병렬 작업** — 공통 변경 먼저 병합 → 독립 작업별 `main` 대상 PR. 선행 변경의 영향을 받은 PR은 재검증.
- **예시** — 문서 데이터와 상세 화면 준비 후, 목록 정렬과 목차 개발 병행.

```sh
git worktree list
git fetch origin
git worktree add --no-track -b feat/doc-toc ../limstack-toc origin/main
```

## 리뷰와 학습

- **언어** — 커밋·PR 제목과 본문은 한국어. 접두사·기술명은 원문 허용. 예시 `fix: 공개 목록에서 초안 제외`.
- **PR 본문** — 변경 이유, 먼저 볼 파일, 확인 방법·결과, 미확인 항목.
- **개발·리뷰** — `ponytail:ponytail` 적용. 코드의 필요성과 기존·표준 기능 확인. 성능 차이는 실제 입력으로 검증. 오류 처리·가독성 유지.
- **학습** — AI는 PR마다 실습이나 질문 하나 제안. 예시 “`publish` 생략 시 공개 여부는?”
- **사례 기록** — `~/documents/markdowns/knowledge/`에 한국어 파일명 사용. 문제·선택 이유·결과·적용 조건·PR 링크 기록. 같은 주제는 기존 글에 추가.
